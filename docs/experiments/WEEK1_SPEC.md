## 已获授权的范围

任务划分核验、实际成本审计、普通采样和随机选点对照、CPU检查与GPU短程检查，
检查通过后先启动普通采样150轮，随后运行随机选点。原检查点和历史运行保持不变。

## 比较组

| 组 | 自然轨迹/任务 | 分支 | 信用 | 成功分支辅助学习 |
|---|---:|---|---|---|
| P | 8 | 无 | 纯Prob | 无 |
| N | 10 | 无 | 纯Prob，所有自然样本进入PPO | 无 |
| R | 8 | 合格位置随机排序 | 原IRGO重算 | 原IRGO |
| F | 8 | 原IRGO启发式排序 | 原IRGO重算 | 原IRGO |

每轮16任务，均150轮、相同初始权重与基础更新参数。N固定每任务增加2条自然
轨迹，独立于成功/失败结果，不是失败后不断重试。N、R、F的每轮物理环境调用
**上限**均2400：N为16×10×15；R/F为16×8×15+480。R/F仍有32条分支上限。
这不是已实现“实际成本严格相等”：必须记录实际物理调用、有效动作、生成
输入/输出token、前缀重放、候选生成和更新工作量，在实际成本轴上比较。
如实际成本明显不同，不能只凭第150轮成功率声称采样效率更高。

N/P可保留只读信用审计，但不得偷偷生成搜索提议或调用分支。全失败率一律
按每组前8条自然轨迹定义；N另外报告全部10条结果。PPO实际处理样本不同的
工作量应公开，不将该端到端对照称为固定优化工作量的证据质量实验。

R只随机化合格上下文的位置排序；候选生成、动作排序、每任务两个上下文、
预算、任务调度优先级、停止规则、Q/V/A更新和辅助损失与F一致。

## 新协议的任务身份

旧代码的每worker种子会改变商品价格、目标顺序，先打乱再按索引划分不足以
保证真实任务不重合。新协议固定商品数据与环境生成种子，按真实结构身份和
标准化指令的连通分组划分，禁止相同结构目标或相同指令跨训练/开发/测试。
商品库仍共享1000商品，不能称为商品泛化。

任务清单保存原环境目标索引、结构身份、指令指纹和完整来源哈希；同组各方法
用相同训练任务序列和固定开发任务。训练随机性与环境生成种子分开记录。
最终保留测试集只建立清单，不在本周调参时执行模型评测。

新划分上的P/F也需重训；旧结果只有历史参照资格，不能补进新的多种子主表。
若缺少完整150轮的逐任务/逐轮成本记录，审计标记“资料不全”，不以第10轮
或前9轮覆盖的记录代表全部150轮。

## 检查边界

沿用用户批准的三个行为边界编写测试：

1. 数据协议：真实任务身份不跨集合；相同种子得到相同任务序列；清单不匹配时拒绝执行。
2. 采样控制：预算上限、零分支零查询、随机选点只改变位置、全失败使用固定8条口径。
3. 训练入口：配置来源可追溯、输出不覆盖、GPU检查与有效更新通过才启动长训。

审查固定点为上述已发布提交，规范来源为README、方法/复现说明和本文件。
本周不会依据新的保留测试结果选择checkpoint或改方案。
